# MY-MOTIONS.md — 把动效改成自己的

用户说「把这个效果改一版」「做成我的动效」「从空白开始」时读本文件。两条路：**改库里的效果**，或**从空白做一个新效果**。和库效果一样按名字调用；库更新不会覆盖它们。

## 放在哪

确认之前是草稿，放当前视频工程的 `analysis/my-motions/<slug>/`。确认之后放：

```text
~/remotion-my-motions/<slug>/
├── motion.json         元数据（含 based_on / borrows / custom:true）
├── MOTION.md           效果规则卡（同库卡结构）
├── CHANGES.md          一行一处改动：改了什么 / 原来是什么 / 为什么
├── demo.tsx            最小可运行示例
├── still.png           确认过的效果帧
└── preview.mp4         5~10 秒演示片（可选）
```

`~/remotion-my-motions/README.md` 是索引：每个效果一行（中英文名、slug、基础效果、一句话、目录路径）。后续会话靠它按名字找到用户效果。**永远不要写进库的 `effects/`，也不要改 `scripts/effects.json`**——那是库的所有者文件。

## 流程

### 1. 从哪开始

- **改库效果**：用户点名一个效果 → 完整读它的 `MOTION.md`。没点名时，给 2~3 个适合用途的候选让他选。
- **从空白做**：用户描述想要的动效（或给一张参考图）→ 选一个最接近的库效果当**技术基础**（代码从哪里长出来），最多再从 1~2 个效果借动作。把选择和理由各一行说清楚，作为第一个问题。

### 2. 一次问一个问题

- 用结构化提问（可用工具时），2~3 个选项 + 推荐项放第一个 + 自由描述放最后；没有工具就用短编号列表。
- 每次问题都要有推荐和理由，理由来自基础效果卡和用户已经说过的话。**能查到的不要问**（基础卡、索引、用户文件）。
- 最多约 10 个问题。用户说「你定」就把剩余推荐一次列完，直接往下走。
- 问完给一段简短总结：**每项决定、改前改后、代价**，等用户明确同意再写文件。

按这个顺序问（跳过已说清的）：

1. **用途**：做哪类视频、给谁看、发在哪 → 决定幅面与运动密度。
2. **改什么**：
   - 改库效果 → 说明哪些部分可以安全改（时序/时长、触发词、颜色、材质、运动质感），哪些改了就变成另一个效果（本质、实现引擎）。
   - 从空白 → 先定本质（一句「它是什么」+ 一句「它不是什么」），再定材质与渲染。
3. **逐项**：触发词与时机 → 画面构成 → 原生动作 → 坑 → 变化空间。
4. **名字**：中文名、英文名、slug（不能和库效果或索引里已有行重名）。

把模糊愿望变成选项，别默默改：

| 用户说 | 通常意味着 |
|---|---|
| 更高级 / premium | 更少颜色、更强明暗对比、更慢运动、更多留白 |
| 更活泼 | 更亮的强调色、踩点切、回弹 easing、更密的运动 |
| 更安静 | 更慢、停稳更长、同时动的元素更少 |
| 像我们品牌 | 品牌色做强调色（不是底色）、品牌字体做标题、片头片尾放 logo |

### 3. 写下来

在草稿目录写三件套：

- `MOTION.md`：改库效果就**完整复制基础卡再改写**（不留「见基础」的空洞）；从空白就按库卡八节写全。标题下加一行 `Based on <基础效果名> (<slug>) from remotion-motion-lib.`（从空白写 `Made from a blank page; technique base: <slug>.`）。
- `CHANGES.md`：一行一处决定（section / 原值 / 现值 / 原因）。
- `motion.json`：字段同库卡，额外加 `based_on`、`borrows`（数组，可空）、`custom: true`、`library_version`、`created`。

### 4. 证明它长这样

用真实代码渲**一张效果帧**（`remotion still`），对照 `MOTION.md` 检查一次。

- 改库效果：再用基础参数渲同一帧，两版并排（基础在左），只让改动不同。
- 从空白：单独展示，有参考图就并排。

把帧存成 `still.png`，**给用户看并等回复**。还要改就更新 `MOTION.md` / `CHANGES.md` 重渲；两轮还不对就说明原因并建议更接近的基础。

### 5. 5~10 秒演示

演示片只证明动效成立，不做完整视频：用用户给的短句或一句简单的示例台词；**每个 `CHANGES.md` 的改动至少出现一次**；片的主题/台词不要抄基础效果的 demo。存成 `preview.mp4`，`demo.tsx` 必须能独立运行。

### 6. 收下来

给用户看演示片：路径 + 每处改动在哪一秒能看到。然后问：

1. **收成我的效果（推荐）**：检查名字/slug 未占用 → 把草稿目录拷到 `~/remotion-my-motions/<slug>/` → 在 `~/remotion-my-motions/README.md` 加一行 → 跑 `python scripts/build_library.py` → 告诉用户以后怎么说名字调用。
2. **再来一轮**：按意见改完重渲，再问一次。
3. **先不收**：留在工程目录，告诉用户以后说「把 <路径> 里的效果收成我的」即可。

只有收下来的才算用户的效果：会被列在索引里、能按名字找到。

## 用起来

- 每次会话开始先读 `~/remotion-my-motions/README.md`（如果存在），用户点名时先在自己的目录里找。
- 读自己效果的 `MOTION.md` 代替库卡；实现先看自己的 `demo.tsx`，再看基础效果。
- 演示片只是一个例子，**不要复用它的台词、镜头和时间轴**。
- 按 `MOTION-DIRECTOR.md` 的正常流程挑效果、按 `MOTION-TECHNIQUE.md` 实现与质检。

## 修改与库更新

- **不满意**：只改用户要求改的部分，更新 `MOTION.md`、`CHANGES.md`，重渲 `still.png` 与 `preview.mp4`，再跑生成脚本。
- **库更新后**：如果 `based_on` 效果的 `MOTION.md` 自 `library_version` 起变过，提一次并问是否把有用的修正合并进用户副本。**不要不问就改。**
- **用户效果不属于库**：成片里不需要署名，也不受库的版本变化影响。
