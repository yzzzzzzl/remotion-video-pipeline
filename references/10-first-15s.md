# 开头 15 秒：黄金窗口强制规范

> 阶段 4 / 5 的硬约束，优先级等同于画面四条铁律。守不住 = 「生硬、没有吸引力、引起不了看下去的欲望」。
> 来源：11-19 一次真实返工——某条 3:09 成片的前 8 秒只有 1 个镜头页（4 根柱子长完后**静止 6 秒**），被用户当场打回。改完后 7 页帧级快切 + 常驻科技 HUD，通过。

**这一节不新增确认门。** 1.2.0 的「只打断两次」（G1 / G2）继续有效：画风、特效、切几页按配方卡与主题自行决定，**不要因此再问用户一次**；只有用户主动提意见时才调整。见 `09-interaction-gates.md`。

---

## 0. 为什么单独管

- 前 15 秒决定完播率。正片靠「观点页↔解释页」维持结构感（`04-shot-design.md`），开场靠**信息密度 + 运动密度**抢注意力，两套节奏标准不同。
- 开场的节奏指标比正片**严一个量级**：正片 4~15 秒/页，开场 1~2.5 秒/页。这是 `04` 的唯一例外，写在这里避免冲突。
- 但画面四条铁律（`08-screen-rules.md`）在开场**更严**，不是放松：页越短，越容易做成「整页一闪而出」或堆字。

---

## 1. 五条硬指标（可验证，全绿才算过）

| # | 指标 | 数值（30fps） | 怎么验 |
|---|---|---|---|
| 1 | **镜头页数** | 0–450 帧（前 15s）内 **≥ 6 页**，建议 7~9 页 | 数 `CH0_CUTS` 数组长度 |
| 2 | **单页时长** | ≤ 2.5s（75 帧）；**首屏页 ≤ 1.5s（45 帧）** | 相邻 `from` 之差 |
| 3 | **首帧就在动** | frame 0 起必须有运动，第 1 帧不许是排好的静态版式 | 抽 frame 0 / 3 |
| 4 | **静止上限** | 任何元素连续静止 **≤ 1.5s（45 帧）**——比铁律四的 3s 严一倍 | 任取 1.5s 抽 3 帧，全同即违规 |
| 5 | **前 3 秒有 Hook** | 0–90 帧内必须出现「数字冲击 / 反常识断言 / 悬念」之一 | 看 P0、P1 文案 |

**第六条（画风）**：开场色板 **必须等于正片色板**（同一个 `C`），只是提高运动密度与对比度。开场炫酷、正片突然朴素 = 断裂；`Video.tsx` 的全局背景色也要同步换成 `C.bgDeep`，否则切章会闪一下。

## 2. 拆分方法：帧级快切，不是行级

正片用 `ShotSequence`（`from` = **本章台词行索引**，见 `04`）。开场要在一句台词里切 2~3 页，行索引不够用，所以改用**帧级快切序列**（`from` = **本章内帧号**）：

```tsx
// 开场专用：from 是帧号，不是行索引
type OpCut = { from: number; Comp: React.FC<ShotProps> };
const CH0_CUTS: OpCut[] = [
  { from: 0,   Comp: OpImpact },    // 0–44    数字冲击
  { from: 44,  Comp: OpDataFlood }, // 44–88   代码洪流
  { from: 88,  Comp: OpTerminal },  // 88–156  终端打字机
  { from: 156, Comp: OpMyth },      // 156–200 误区大字
  { from: 200, Comp: OpBreak },     // 200–240 划掉 / 拆开看
  { from: 240, Comp: OpCore },      // 240–311 核心物件全息卡
  { from: 311, Comp: OpAnyTool },   // 311–408 节点连线
];
```

**切点对齐规则**
1. 优先把切点对齐**台词起点**（查 `timeline.lines[i].startFrame`，别估秒数）。
2. 需要切在句中时，`at(i)` 会返回负值 —— 该页改用**页内帧节奏逐段揭示**（0 / 8 / 16 / 24 帧），并在代码注释写明「此页切在句中，故用页内节奏」。这是 `08` 铁律三的合法例外，但必须留注释，否则下一个人会以为是拍常数。
3. 转场用 **4 帧淡入 + 24px 横滑**（比正片的 7 帧淡入 + 36px 上滑更利落），页尾 3 帧淡出。
4. 每页仍要有 **1 个完整信息点**。别为了凑页数把一句台词碎成 5 页——那是幻灯片不是快切。

**台词行数不够怎么办**：开场稿至少 4~6 句（写稿阶段就定，`02-script-and-lines.md`）。不足就按 `02` §2.2 再拆行，或让一句长台词配 2 页；**不许靠加字凑时长**。

## 3. Hook 叙事曲线（写稿阶段就要定）

四拍，和 `02` §2.1 的「否定式 Hook / 结尾回扣」对齐：

| 拍 | 时间 | 作用 | 模板 | 画面 |
|---|---|---|---|---|
| ① 冲击 | 0–1.5s | 让人停下来 | 具体数字、反常识断言、画面异常 | `487,392` 滚动冲屏 + 故障抖动 + 均衡器 |
| ② 误区 | 1.5–5s | 建立「大家都以为」 | 「很多人以为这是 X 的魔法」 | 代码雨 / 终端窗口（暗示「其实是代码」） |
| ③ 拆穿 | 5–8s | 否定并制造悬念 | 「其实拆开看，核心是 Y」 | 红色删除线划掉 X + `FALSE` 印章 +「拆开看 →」 |
| ④ 预告 | 8–15s | 给出本片主角 | 「Y 在手，用什么工具都能跑」 | 核心物件全息卡（`SKILL.md`）+ 四节点连线点亮 |

- **前 3 秒不放 logo、不放「大家好」、不放背景介绍**——这些是完播率杀手。
- ① 的具体数字要来自内容本身（点赞数、年份、页数、耗时），不要编一个无关大数。
- 开场抛出的矛盾/悬念，**结尾必须解决**（`02` §2.1），别用「点赞关注」软结尾。

## 4. 特效库（按主题挑，全部确定性）

> **分工**：本节是**开场装饰特效**（给画面质感、让「一直在动」）。正片「讲到什么就演什么」的**讲解型语义动作**（逐项进场、走线、扫描、打字、合流…）见 `13-motion-library.md`，两者可叠加但不要混用——开场别堆语义动作，正片别只上装饰。

| 特效 | 实现要点 | 适合主题 | 成本 |
|---|---|---|---|
| 数字滚动计数 | `interpolate(local,[2,32],[0,N])` + 千分位 `fmt()` | 数据 / 成绩 / 规模 | 低 |
| RGB 故障字 | 双色偏移 + `sin(local*1.9)*3px` 抖动 | 科技 / 反差 | 低 |
| 均衡器 / 柱状生长 | `26 + abs(sin(local*0.28 + i*0.85))*96` | 数据 / 音频 / 增长 | 低 |
| 代码雨 / 十六进制数据轨 | 确定性 seed：`(i*73 + floor(local/3)*17) % 4096` | 技术 / AI / 工具 | 中 |
| 终端打字机 | `pctOf(local, start)` 逐行 + 光标 `sin` 闪烁 | 工具 / 教程 | 中 |
| 常驻 HUD 层 | REC 状态、解码帧号、四角 L 框、扫描线、侧边刻度 | 技术 / 系统感 | 中 |
| 全息卡揭示 | `clipPath` 展开 + 渐变光带扫描 | 产品 / 核心概念 | 中 |
| 删除线 + 印章 | `width: strike*108%` + 旋转方框 `FALSE`（不用圆） | 破除误区 | 低 |
| 节点连线 | SVG 连线 + 节点逐个 pop 点亮 | 流程 / 生态 / 兼容性 | 中 |
| 缓推近 / 书页翻动 / 烫金浮出 | `scale 1.0→1.06`、`transform` 翻页、遮罩揭示 | 书籍 / 人文 / 历史 | 中 |

**六条实现铁律**
1. **禁止 `Math.random()`**。Remotion 逐帧独立渲染，随机值会让画面每帧抖动。循环动效一律用 `sin(local/k + i*phase)` 或 `floor(local/n)` 派生的确定性序列。
2. **不用大圆环 / 圆圈**当画面正中装饰（用户明确不喜欢）。改用 L 形角标、方括号、终端框、卡片描边。
3. **HUD 低透明度**（0.3~0.6）、`pointerEvents:none`，不抢主体。HUD 里的装饰小字仍是文字元素，计入 `08` 铁律二的「一屏 ≤5 个」，主体区建议 ≤3 个。
4. **避开安全区**：字幕条、右上声波头像、右下帧计数器、左上章节标签（坐标见 `05-visual-system.md`）。装饰行放字幕条**上方**的空隙，别压字幕。
5. **HUD 只在第 0 章渲染**，章末必须完全消失——切章后抽 1 帧逐项确认无残留（REC / 数据轨 / 四角框 / 底部说明）。
6. **不引入新依赖**：全部特效只用 Remotion 内置 `interpolate` / `Easing` + 原生 CSS / SVG，不需要额外 npm 包（依赖清单仍以 `00-dependencies.md` 为准）。

## 5. 更贴合主题的画风（重点）

「炫酷」不等于「一律上代码雨」。讲《资本论》还放终端窗口就是**不贴题**。

### 选择流程

1. 阶段 1 的**配方卡**记下主题与色彩倾向：模式 A（`01`）靠拆片取色，模式 B（`11-topic-only.md` §2）靠主题归类推导，两者字段一致。
2. 从下表选一套「色板 + 字体 + 母题」，写进 `C`（**全片共用**，不只是开场）。
3. 开场从这套母题里挑 3~4 个特效做高密度版本；正片沿用同一套 token，只降低运动密度。
4. `Video.tsx` 全局背景色 = `C.bgDeep`；换主题时三处一起改（色板、字体、背景）。

### 主题 → 画风映射表

| 主题 | 底色 / 主色 / 强调 | 字体 | 开场母题 | 正片元素 |
|---|---|---|---|---|
| 技术 / AI / 工具教程 | 深黑 `#0A0D09` + 荧光绿 `#B6E388` + 青 `#6FE3D2` | `MONO` + 黑体 | HUD、代码雨、终端、节点连线 | 代码窗口、流程线、帧号 |
| 书籍 / 人文 / 历史 | 深棕 `#171207` + 烫金 `#D4AF37` | `SERIF` 衬线 | 书页翻动、烫金浮出、年代卡、遮罩揭 | 样片预览框、词卡、竖排标题 |
| 财经 / 数据 | 深蓝 `#0B1526` + 蓝 `#3B82F6`；**涨红跌绿** | 黑体 + `MONO` 数字 | 数字滚动、柱状生长、K 线 | 图表卡片、对比栏 |
| 科普 / 教育 | 深蓝 + 青 `#22D3EE` | 黑体 | 网格、示意图、流程连线 | 卡片墙、总览页复用 |
| 极简观点 | 黑白 + 单一强调色 | 粗黑体 | 大字故障、删除线、位移 | 关键词页、勾选收束 |

**三条禁止**
- ❌ 一套模板通吃所有主题（先在配方卡里定主题，再选画风）。
- ❌ 开场与正片两套色板 / 两套字体。
- ❌ 为了炫酷往画面加字——科技感靠**运动与结构**，不靠堆标签（`08` 铁律二）。

## 6. 与四条铁律的关系（开场加严）

| 铁律（`08`） | 开场额外要求 |
|---|---|
| 一 · 禁止整页出现 | 第 3 帧必须只有 1~2 个元素；页越短越要错开进场（0 / 8 / 16 帧） |
| 二 · 只放关键词 | 主体 ≤3 个文字块，单个 ≤12 字，不许整句台词；HUD 小字低透明度另计 |
| 三 · 查字幕锚点 | 切点对齐台词起点；句中切页改用页内帧节奏**并写注释** |
| 四 · 静态撑不了场 | 静止上限从 3s 收紧到 **1.5s**；每页至少 1 个永动元素 |
| 五（新增）· 画风一致 | 开场 = 正片同一套 `C` / 字体 / 背景；HUD 不越界、不残留到下一章 |

冲突时优先级不变：**不整页出现 > 只放关键词 > 查字幕锚点 > 加运动 > 画风一致**。信息超载的唯一解法仍是**拆页**。

## 7. 质检清单（并入 `06` 阶段 6、`08` 自检卡）

- [ ] 前 15s 镜头页 ≥ 6，单页 ≤ 75 帧，首屏页 ≤ 45 帧；切点对齐台词或已注明句中切
- [ ] 抽检帧覆盖：`frame 0` / 每页页首 / 每页中段 / 每页页尾 / **450（切章后一帧）**
- [ ] frame 0 与第 3 帧是「半成品」，无 1.5s 完全静止
- [ ] 主体文字 ≤3 块、无整句、无溢出；字幕条与头像区域干净
- [ ] 450 帧之后**无任何 HUD 残留**（逐项核对 REC / 数据轨 / 四角框 / 扫描线 / 说明行）
- [ ] 开场色板 = 正片色板，全局背景色一致
- [ ] `tsc --noEmit` 通过；全片渲染后 `ffprobe` 时长不变（只动画面，音轨/时间轴零改动）

> 全片渲染约 6× 实时，开场特效（逐帧代码雨 + HUD）会让合成更慢。务必先静帧全绿再渲，别拿全片试错。

## 8. 反模式

- **前 8 秒一个页面**（实测被退回）：元素长完就静止，观众以为卡住。
- `Math.random()` 做粒子 / 光点 → 逐帧抖动。
- 通用科技模板套所有主题；或开场深黑绿、正片突然深蓝。
- HUD 压住字幕条 / 声波头像，或切章后残留。
- 开场堆 5 行字讲背景、放 logo、说「大家好」。
- 为凑页数把一句话碎成 5 页，每页没有完整信息点。
- 只改开场组件却忘了改 `Video.tsx` 全局背景色 → 切章闪一下。
- 拿这套规范去问用户「你想要什么画风」——**这不是新的确认门**。

## 9. 实测案例（11-19）

- 成片：3:09 / 1920×1080 / 横屏，主题「AI 动画视频的核心是个 Skill +《资本论》样例」。
- 原状：`HookBars` 一页独占 frame 0–238，4 根绿柱长完后静止 6 秒，科技感几乎为零。
- 改后：`src/scenes/Opening.tsx` 新建 7 页帧级快切（切点 0/44/88/156/200/240/311/408）+ `OpeningHUD` 常驻层（REC、解码帧号、十六进制数据轨、四角 L、扫描线、刻度）；`Scenes.tsx` 把 `HookScene` 指向新开场。
- **只动画面**：音轨、`scenes.json`、`timeline.json` 全部零改动；后续章节与上一版完全一致。
- 质检：11 张静帧逐页核对（含页首空档、P1 `CODE` 加暗色衬底防叠花、P4 中段元素齐全、420 帧 HUD 无残留）+ `tsc` + `ffprobe` 189.3s 不变。
- 代价：代码雨/HUD 让合成明显变慢，质检帧数从 6 增到 11。

## 10. 可复用资产

`assets/components/Opening.tech.tsx` —— 上述实测的**已验证实现**（7 页 + HUD + 帧级快切），横屏 1920×1080。

**用法**
1. 把 `Chrome.tsx`、`ShotEngine.tsx` 拷进 `src/components/`，`Opening.tech.tsx` 拷进 `src/scenes/`（它按 `../components/Chrome` 与 `./ShotEngine` 解析；资产目录里三者同级存放只是为了归档）。
2. `Video.tsx` 的 `SCENE_COMPONENTS[0]` 指向 `Ch0Scene`（或 import 时改名 `HookScene`）。
3. 按主题改文件头的 `C` 调色板（第 5 节映射表）、`CH0_CUTS` 各页文案常量、`FONT/MONO`；**同时**把 `Video.tsx` 全局背景色改成 `C.bgDeep`。
4. 默认横屏 1920×1080 直接用；仅当用户明确要竖屏时才按下面换算表改坐标，先渲 3 帧确认安全区。

**默认横屏 1920×1080 → 竖屏 1080×1920（按需覆盖）坐标换算**

| 项 | 横屏 | 竖屏 |
|---|---|---|
| `Center` inset | left/right 120, top 130, bottom 210 | left/right 60, top 180, bottom 420 |
| 字幕条 top | 892（`05` 默认安全区） | 1580 |
| HUD 底部说明行 | top 892 | top 1520 |
| 画框 `Corner4` | x70 y110 hx1780 hy770 | x50 y200 hx980 hy1200 |
| 左十六进制数据轨 | left 84, top 236 | left 40, top 420 |
| 右侧刻度 | right 92, top 250 | right 40, top 440 |
| 水平扫描线范围 | 130 ~ 870 | 200 ~ 1400 |

> 组件内 `C` 是**自带**的（含 `greenBright` 等字段），不依赖 `Chrome.tsx` 的 token 版本；换主题只改这一个常量即可。
