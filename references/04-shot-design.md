# 分镜设计：观点页 ↔ 解释页交替

这是整套流程最容易被做坏的一环，也是返工最多的一环。第一版做成了「一章一个大画面挂到底」，单页最长停留 60 秒，观众会以为视频卡了。用户的判据很直接：**观点一页，解释拆多页，回到观点页点亮下一条，再切出去解释。**

> **开场例外**：下面 4~15 秒/页、「一页至少扛 1~2 句」的标准只适用于正片章节。第 0 章（开头 15 秒）改用**帧级快切**——≥6 页、单页 ≤2.5s、首屏 ≤1.5s、`from` 用帧号而非行索引。见 `10-first-15s.md`。画面四条铁律在开场仍然生效且更严，不要误以为节奏放宽了。

## 节奏模式

以一个「三句话结论」的章节为例（台词已按句拆好，编号是本章内的行索引）：

```
行0  先说结论，三句话          → 总览页（三张卡片全列出，都不点亮）
行1  第一，提示词不用你写。     → 总览页，卡片①高亮放大
行2  Remotion 是前端项目…      → 解释页 A：代码窗口逐行展开
行3  你要做的是把需求说明白…    → 解释页 A 续（逐字敲出 prompt）
行4  提示词让 AI 自己整理。     → 解释页 B：分工流程（你 → AI）
行5  第二，给参考比给文字管用。  → 总览页，①变绿勾，②高亮
行6  找一个范本发给它…          → 解释页 C：形容词墙划掉 vs 范本卡片
行7  第三，留下的不只是视频。    → 总览页，②变绿勾，③高亮
行8  代码、组件、动画轨迹都留在…  → 解释页 D：资产清单
行9  下次直接复用…              → 解释页 E：复用流程图
```

**关键**：总览页会被复用 3~4 次，每次只改高亮位；解释页每页只承担 1~2 句台词的信息量。

## 镜头表 DSL

每章一个 `ShotDef[]`，`from` 是**本章内的台词行索引**（不是帧！），引擎自动换算时间：

```tsx
type ShotDef = { from: number; Comp: React.FC<ShotProps> };

const CH1_SHOTS: ShotDef[] = [
  { from: 0, Comp: (p) => <Overview1 {...p} hl={-1} /> },  // 总览，无高亮
  { from: 1, Comp: (p) => <Overview1 {...p} hl={0} /> },  // 总览，点亮①
  { from: 2, Comp: Expl1Code },                            // 解释页
  { from: 4, Comp: Expl2Flow },
  { from: 5, Comp: (p) => <Overview1 {...p} hl={1} acc={[true,false,false]} /> },
  { from: 6, Comp: Expl3Compare },
  { from: 8, Comp: (p) => <Overview1 {...p} hl={2} acc={[true,true,false]} /> },
  { from: 9, Comp: Expl4Assets },
  { from: 11, Comp: Expl5Reuse },
  { from: 13, Comp: (p) => <Overview1 {...p} hl={3} acc={[true,true,true]} /> }, // 收束
];
```

引擎（`assets/components/ShotEngine.tsx`）按「当前说到第几句」选镜头，并用相邻两页的 `relStart` 算出本页时长，做 7 帧淡入 + 36px 上滑转场。

## 从稿子到镜头表的做法

1. 通读本章台词，标出**并列关系**（第一/第二/第三、四个格子…）→ 这些是总览页的复用点
2. 每句解释性台词分配 1 个解释页；两句同一逻辑可共用一个页（`from` 只写第一句）
3. 估算每页时长 = 该页覆盖台词的时长之和，**目标 4~15 秒**；超过 20 秒就说明该页要再拆
4. 章节最后一页做「收束」（全部点亮 / 合并成一个结论 / 一句金句 + 勾选）
5. **逐页判断是否需要外部素材**：按 `12-asset-sourcing.md` §0 的三档判据过一遍——A 必用（没有它就假）、B 优先用（有它明显更好：贴题实拍 / 图标 / 纹理 / 界面截图 / 音效，**默认找**）、C 仍用代码。A / B 档都写进 `analysis/配方卡.md` 的「素材清单」并过版权/画风/元素三关；只有 C 档和过不了关的才用代码。**先定分镜再找素材**，反过来会退化成一页一图的 PPT 味

实测：80 句台词 → 34 个镜头页，单页 4~15 秒，成片 3 分 52 秒。

## 反面案例

- **开场沿用正片节奏**：前 15 秒只给 1~2 页，元素长完就静止 → 生硬、没有吸引力（实测被用户当场打回，见 `10-first-15s.md`）
- **一章一页**：单页最长 60 秒，观感是 PPT 卡死
- **总览页只在开头出现一次**：后面全是解释页，观众失去结构感
- **每句都换页**：碎成幻灯片，反而更乱；一页至少扛 1~2 句
- **一整页元素同时出现**：AI 味 PPT 感；必须逐个进场并卡台词帧
- **先囤素材再定分镜**：会为了用完素材硬塞页，退化成「一页一图」——素材必须跟着分镜走（`12` §1）
- **网图铺满主体区当背景**：违反铁律一，即使图再贴题也不行（`12` §7）

## 常见 bug：错位一格

`from` 写错一格，会表现为「解释说到一半，总览页突然亮起来」。症状是台词和画面对不上但时间轴没错。

**必检方法**：改完镜头表后，对每个 `from` 取 `lines[from].startFrame + 10` 渲染静帧，看画面内容是否匹配该句台词。别只看章节开头。

帧换算：`frame = line.startFrame + 10`（30fps 下 +10 帧 ≈ 进场动画刚完成）。

## 页面组件写法约定

- 组件只接收 `{ local, len }`（本页内帧号 / 本页帧长），**不要**在组件里判断全局时间
- 进场统一用 `popIn(local, delay)`（见 `Chrome.tsx`），`delay` 用本页内帧号，错开 8~12 帧
- 循环呼吸类动效（光晕、声波、光标闪烁）用 `local` 驱动，保证每页重新起势
- 同一页面组件的不同状态用 props（`hl` 高亮位、`acc` 已完成位），不要复制成多个组件
